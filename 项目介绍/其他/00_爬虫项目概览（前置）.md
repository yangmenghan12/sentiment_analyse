# Sentinel Crawler 项目概览与启动说明

## 1. 项目定位

Sentinel Crawler 是一个多平台热点与社交媒体内容爬取系统，整体流程是：

1. 从新闻热榜【https://newsnow.busiyi.world/c/hottest】 API 收集每日热点新闻。
2. 使用 LLM 从热点新闻中提取关键词与摘要。
3. 将关键词保存到数据库 `daily_topics`。
4. 使用 MediaCrawler【https://github.com/NanmiCoder/MediaCrawler】 按关键词在社交平台爬取内容。 
5. 通过 FastAPI + Vue 前端提供控制台、任务状态、新闻、话题和平台配置查询。

## 2. 技术栈

### 后端

- Python 3.11 ~ 3.12

### 前端

### 依赖管理

- Python 使用 `uv`

## 3. 核心目录结构

```text
app/

  deep_sentiment/

```

## 4. 核心运行流程

### 4.1 话题提取 Broad Topic

入口：`app.pipeline.CrawlerPipeline.run_broad_topic()`

流程：

1. `NewsCollector` 调用新闻抓取器收集热点新闻。
2. 新闻保存到 `daily_news`。
3. `TopicExtractor` 调用 LLM 提取关键词和新闻摘要。
4. 关键词与摘要保存到 `daily_topics`。

相关文件：

- `app/broad_topic/news/fetcher.py`
- `app/broad_topic/news/collector.py`
- `app/broad_topic/topic/extractor.py`
- `app/db/repository/news_repository.py`
- `app/db/repository/topic_repository.py`

### 4.2 深度爬取 Deep Sentiment

入口：`app.pipeline.CrawlerPipeline.run_deep_sentiment()`

流程：

1. `KeywordManager` 从 `daily_topics` 读取指定日期关键词。
2. `PlatformCrawler` 注入 MediaCrawler 配置。
3. 调用 MediaCrawler 对指定平台执行关键词搜索爬取。
4. 内容数据由 MediaCrawler 自己的存储逻辑写入对应平台表。

相关文件：

- `app/deep_sentiment/keyword_manager.py`
- `app/deep_sentiment/platform_crawler.py`
- `MediaCrawler/media_platform/*`

### 4.3 完整流水线 Pipeline

前端选择 `pipeline` 时，实际由 `app/web/services/crawl_worker.py` 分两段执行：

1. 先执行话题提取。
2. 成功后推送第二阶段日志。
3. 再执行深度爬取。

任务由 `TaskManager` 在子进程中执行，避免阻塞 FastAPI 主进程。

## 5. 后端 API 概览

### 健康检查

- `GET /api/health`

### 数据库初始化

- `POST /api/init-db`

### 平台与配置

- `GET /api/platforms`
- `GET /api/config/options`

### 新闻

- `GET /api/news/sources`
- `GET /api/news?target_date=YYYY-MM-DD&source=xxx`

### 话题

- `GET /api/topics?days=7`
- `GET /api/topics/{target_date}`
- `GET /api/topics/{target_date}/keywords`

### 爬虫任务

- `POST /api/crawl/broad_topic`
- `POST /api/crawl/deep_sentiment`
- `POST /api/crawl/pipeline`
- `GET /api/crawl/tasks?limit=20`
- `GET /api/crawl/tasks/{task_id}`
- `POST /api/crawl/tasks/{task_id}/stop`

### WebSocket

- `WS /ws/crawl/{task_id}`

用于实时接收任务阶段、日志、结果等事件。

## 6. 环境变量

项目读取根目录 `.env`。

常用配置：

```env
DB_DIALECT=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=root
DB_PASSWORD=root
DB_NAME=media_crawler
DB_CHARSET=utf8mb4

CRAWLER_LLM_API_KEY=你的模型 API Key
CRAWLER_LLM_BASE_URL=你的 OpenAI-compatible API 地址
CRAWLER_LLM_MODEL_NAME=deepseek-chat

NEWS_API_BASE_URL=https://newsnow.busiyi.world

CRAWLER_MAX_KEYWORDS=5
CRAWLER_MAX_NOTES=20
CRAWLER_LOGIN_TYPE=qrcode
CRAWLER_HEADLESS=False
CRAWLER_ENABLE_CDP_MODE=False
CRAWLER_DISABLE_SSL_VERIFY=False

WEB_HOST=0.0.0.0
WEB_PORT=9000
```

说明：

- `CRAWLER_ENABLE_CDP_MODE=True` 可让 MediaCrawler 尝试使用真实 Chrome/Edge CDP 模式，适合抖音等容易风控的平台。
- `CRAWLER_HEADLESS=False` 会显示浏览器窗口，方便扫码、验证码和调试。
- `CRAWLER_DISABLE_SSL_VERIFY=True` 只建议在公司代理或本地抓包代理导致证书问题时临时使用。

## 7. 启动步骤

### 7.1 安装后端依赖

在项目根目录执行：

```bash
uv sync
```

如果 Playwright 浏览器未安装，执行：

```bash
uv run playwright install chromium
```

### 7.2 安装前端依赖

```bash
cd frontend
npm install
```

### 7.3 启动后端

推荐使用：

```bash
uv run uvicorn app.web.main:app --host 0.0.0.0 --port 9000 --reload
```

也可以使用：

```bash
uv run python -m app.web.main
```

注意：`frontend/vite.config.ts` 当前将 `/api` 和 `/ws` 代理到 `http://localhost:9000`，所以后端建议监听 `9000` 端口。

### 7.4 启动前端

```bash
cd frontend
npm run dev
```

前端默认地址：

```text
http://localhost:5173
```

### 7.5 初始化数据库

启动前后端后，在前端设置页执行数据库初始化；或者直接调用：

```bash
curl -X POST http://localhost:9000/api/init-db \
  -H "Content-Type: application/json" \
  -d '{"host":"127.0.0.1","port":3306,"user":"root","password":"root","db_name":"media_crawler","charset":"utf8mb4"}'
```

## 8. 前端使用流程

1. 打开 `http://localhost:5173`。
2. 在设置页检查数据库连接和初始化状态。
3. 在爬取页选择任务类型：
   - `broad_topic`：只收集新闻并提取关键词。
   - `deep_sentiment`：使用已有关键词爬取平台内容。
   - `pipeline`：先提取关键词，再爬取平台内容。
4. 选择平台、日期、关键词数量、爬取数量和登录方式。
5. 启动任务后通过 WebSocket 实时查看日志。
6. 在新闻页查看 `daily_news`。
7. 在话题页查看 `daily_topics` 与关键词。

## 10. 数据表说明

### 项目业务表

由 `app/db/models.py` 管理：

- `daily_news`：每日新闻热榜数据。
- `daily_topics`：每日关键词、摘要和话题分析结果。

### MediaCrawler 内容表

由 MediaCrawler 自己的 ORM 管理，例如小红书、抖音、B站等平台内容表。

初始化数据库接口会尝试同时创建项目业务表和 MediaCrawler 相关表。
